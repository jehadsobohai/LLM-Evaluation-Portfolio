Medical Patient Education Prompt Engineering

Design and evaluation of an LLM prompt that explains hypertension to a newly diagnosed patient using simple, non-medical language.

Project Overview

This case study demonstrates a structured prompt engineering workflow using Google Gemini (3.6 Flash) for a patient education task. It illustrates how iterative prompt refinement significantly improves response empathy, clarity, and safety without changing the underlying model.

Evaluation Breakdown (Initial Response)

Performance assessment of the unprompted baseline across core clinical communication criteria.

Criterion Score Assessment Summary
Medical Accuracy 5.0 / 5 Completely accurate; provides comprehensive details on hypertension causes and complications.
Clarity 3.5 / 5 Clear explanation overall, but technical terms (systolic, diastolic, mmHg) confuse lay readers.
Instruction Following 4.0 / 5 Explains hypertension as requested, but produces far more detail than necessary for a basic query.

Baseline vs. Refined Prompt Comparison

Initial Output (Unrestricted)

"Hypertension is the medical term for high blood pressure... Measured in mmHg: Systolic (120–129) and Diastolic (<80)... Primary (Essential) vs Secondary..."

Issue: Too technical, lacks empathy, reads like a general health article.

Refined System Output (Optimized)

"First, take a deep breath—you are going to be okay, and we can manage this together. Think of your blood vessels like a garden hose..."

Outcome: Under 150 words, non-medical language, empathetic, and encourages medical follow-up.

Key Findings & Demonstration

Iterative prompt engineering improves output without changing model weights Role-play instructions successfully enforce patient-friendly tone Strict constraints eliminate complex medical jargon and numerical tables
